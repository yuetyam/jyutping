Plan: Raise the minimum deployment targets from iOS/iPadOS 16 and macOS 13 to iOS/iPadOS 17 and macOS 14.

Status: Steps 1–2 implemented (2026-10-19). Steps 3–4 and runtime validation remain.

## Goal

Make iOS/iPadOS 17.0 and macOS 14.0 the oldest supported systems for the reference app, the keyboard extension, the macOS input method, and the shared Swift packages. Then remove the code that only exists for iOS 16 and macOS 13, and adopt the replacement APIs that become available without availability checks.

The visionOS target of the reference app stays at 1.0. The `Preparing` package stays at macOS 27, because it is a local build-time tool.

Users on iOS 16 or macOS 13 must not be offered a build that they cannot run. The release steps below cover the App Store, the installer package, and the Sparkle appcast.

## Non-goals

- Raising the targets beyond iOS 17 and macOS 14. Code gated on iOS 18, iOS 26, macOS 15, macOS 26, and later stays as it is.
- Moving the app from `ObservableObject` to the Observation framework (`@Observable`). This becomes possible on iOS 17 and macOS 14, but it is a separate refactor and is described under "Optional follow-ups".
- Changing any behavior that users can see on iOS 17+ or macOS 14+.

## Baseline before implementation

### Deployment settings

- `Jyutping.xcodeproj/project.xcproj` (the JSON project format) sets the deployment targets for each target. There are no project-level overrides.
  - `Jyutping`, `JyutpingTests`, and `JyutpingUITests`: `IPHONEOS_DEPLOYMENT_TARGET` `16.0`, `MACOSX_DEPLOYMENT_TARGET` `13.0`, `XROS_DEPLOYMENT_TARGET` `1.0`.
  - `Keyboard`: `IPHONEOS_DEPLOYMENT_TARGET` `16.0`.
  - `InputMethod`, `InputMethodTests`, and `InputMethodUITests`: `MACOSX_DEPLOYMENT_TARGET` `13.0`.
  - `InputMethodDebug.xcconfig` and `InputMethodRelease.xcconfig` do not set deployment targets.
- `platforms: [.iOS(.v16), .macOS(.v13)]` appears in six package manifests: `AboutKit`, `AppDataSource`, `CommonExtensions`, `CoreIME`, `Linguistics`, and `SQLiteWrapper`.
- macOS installer: `packaging/pack.sh` passes `--min-os-version 13.0` to `pkgbuild`, and `packaging/distribution.xml` declares `<os-version min="13.0" />`.
- Sparkle: `InputMethod/Info.plist` points `SUFeedURL` to `https://jyutping.app/appcast.xml`, which is hosted outside this repository.
- The project uses folders synchronized with the file system, so deleting Swift files needs no project-file edits.

### APIs deprecated in iOS 17 / macOS 14 that the code still uses

- The one-parameter `onChange(of:perform:)` closure form is deprecated in iOS 17 and macOS 14. Once the targets are raised, 61 call sites will produce deprecation warnings (this count leaves out the iOS 16 files that will be deleted):
  - `Keyboard/SharedViews/SettingsView.swift` (22), `PressButtonStyle.swift`, `ScrollViewButton.swift`, and `ScrollViewGestureButton.swift`. `ScrollViewGestureButton` is `@available(*, unavailable)`.
  - `InputMethod/Preferences/`: `GeneralSettingsView.swift` (14), `FontSettingsView.swift` (9), `AppearanceSettingsView.swift` (6), `HotkeysView.swift` (4), `InputMemorySettingsView.swift`, and `ReverseLookupView.swift`
  - `Jyutping/macOS/Search/MacSearchView.swift:74`
- Eleven call sites already use the two-parameter or zero-parameter form inside iOS 17+/iOS 18+ code. They need no changes.

## Decisions to confirm before starting

1. **Final release for iOS 16 / macOS 13.** Choose the last version that still supports the old systems (for example, the current `0.85.0` line), and decide whether that line will get any fixes.
2. **Sparkle appcast.** Every appcast item published after the bump must declare `<sparkle:minimumSystemVersion>14.0</sparkle:minimumSystemVersion>`. Without it, Sparkle offers macOS 13 users an update that the installer will reject.
3. **Release timing.** Ship the bump in a regular version (for example, the next minor version) with release notes, not in a patch release.

## Implementation sequence

Each step should be a separate commit that builds on its own, so it can be reviewed and bisected.

### 1. Raise the deployment targets

- `Jyutping.xcodeproj/project.xcproj`: change every `IPHONEOS_DEPLOYMENT_TARGET` from `16.0` to `17.0` (4 targets) and every `MACOSX_DEPLOYMENT_TARGET` from `13.0` to `14.0` (6 targets). Leave `XROS_DEPLOYMENT_TARGET` alone. Prefer editing in Xcode 27 so the JSON project file stays in its canonical form. If you edit it by hand, open the project in Xcode afterwards and check that nothing was rewritten.
- The six package manifests: change `platforms` to `[.iOS(.v17), .macOS(.v14)]`. Leave `Modules/Preparing/Package.swift` alone.
- `packaging/pack.sh`: `--min-os-version 14.0`. `packaging/distribution.xml`: `<os-version min="14.0" />`.
- Build all three schemes and record the new deprecation warnings. Expect the `onChange` warnings and warnings from the `deprecated: 17.0` iOS 16 views. The next two steps remove them.

### 2. Remove the iOS 16 / macOS 13 code paths

Keyboard:

- Delete the four `*IOS16.swift` files and the `else` branches that use them in `CandidateBar.swift`, `CandidateBoard.swift`, and `SidebarPanel.swift`. The `*IOS17.swift` views stay, because iOS 17 is still supported.
- Remove the gate in `Speaker.swift`, `SettingsView.swift:369`, and `NavigationTrailingExpansionButton.swift`, keeping the iOS 17 branch in each.
- `Speech.swift`: turn the `else if #available(iOSApplicationExtension 17.0, *)` branch into the final `else`, and delete the old final `else`. Keep the "Premium Cantonese voices are broken in iOS 17" comment.
- `EmojiMaster.swift`: delete the `16.4` branch and the Emoji 14.0 `else`, and give the `17.4` check a final `else` that filters to `<= 150000`.

Reference app:

- In the six metro views, keep the iOS 17 `List` with `.listSectionSpacing(12)` and delete the duplicate.
- In `LexiconView.swift` and `YingWaaLexiconSectionView.swift`, apply `.fontDesign(.serif)` without a gate.
- In `Jyutping/Speech/Speaker.swift`, keep the iOS 17 / macOS 14 branches. In `Jyutping/Speech/Speech.swift`, make the iOS 17 / macOS 14 branch the final `else`.

Comments and annotations:

- Reword the macOS 13 comments in `InputMemoryExportController.swift` and `InputMemoryImportController.swift`. The controllers still keep state across sidebar navigation, so keep them.
- Leave `introduced: 16.0` annotations on declarations that are still used, such as the `KeyboardInterface` cases and `IOSLegacyContentView`. They are harmless, and `IOSLegacyContentView` is still the iOS 17 path.

Search again to confirm that no `16.`, `iOS 17.0`, `iOSApplicationExtension 17.0`, or `macOS 14.0` gates are left. Do not touch the `17.4` emoji check.

## Release

- App Store: upload the iOS and macOS app builds with the new minimum version. Devices on iOS 16 / macOS 13 keep the last compatible version through the App Store's "last compatible version" mechanism.
- Input method package: build with the updated `pack.sh` and `distribution.xml`.
- Appcast: publish the new item with `sparkle:minimumSystemVersion` `14.0` (see Decisions). Older items stay unchanged, so macOS 13 users stay on the final compatible version.
- Release notes in every locale: state that iOS/iPadOS 17 and macOS 14 are now required.

## Optional follow-ups

Do these separately, after the bump has shipped:

- **Observation framework.** Move `KeyboardViewController` (used through `@EnvironmentObject` in about 194 keyboard files), `InputContext`, `InputMemoryTransferController`, `InputMemoryExportController`, and `InputMemoryImportController` from `ObservableObject`/`@Published` to `@Observable`. This can reduce SwiftUI invalidation in the keyboard, but it touches every key view. It needs its own plan and performance and memory checks in the keyboard extension.
- **Merge the iOS 17/18 view variants** (`*IOS17.swift`) when the minimum is raised to iOS 18.

## Completion criteria

- All targets and package manifests (except `Preparing`) declare iOS 17.0 / macOS 14.0. The installer enforces macOS 14.0.
- No `#available`/`@available` branches remain for iOS ≤ 17.0 or macOS ≤ 14.0, apart from the `17.4` emoji check. The iOS 16 files are deleted.
- No deprecation warnings remain for the one-parameter `onChange`.
- The package tests pass, and all four builds succeed.
- The runtime checks on iOS 17 and macOS 14 are done and reported.
- The documentation, installer read-mes, and `AGENTS.md` show the new minimum versions.
- The appcast item for the first release after the bump declares `minimumSystemVersion` 14.0.
